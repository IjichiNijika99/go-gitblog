# [浅认知：大模型代码和权重](https://github.com/IjichiNijika99/go-gitblog/issues/19)

下载开源模型时，通常都是模型代码几十KB，权重文件却大几个GB，甚至几十GB。
为什么会有这么大的差距？模型的知识在哪里？输入指令后，代码和权重是如何工作得到输出结果的？

### 先搭一个最小模型
假设一个判断天气的模型。
输入两个数：
- 温度
- 湿度

输出一个数：
- 适合出门的分数

分数越高越适合出门。模型结构如下：
```
class WeatherModel:
    def __init__(self):
        self.w1 = None
        self.w2 = None
        self.b  = None

    def forward(self, temp, humidity):
        return temp * self.w1 + humidity * self.w2 + self.b
```
代码给出了出门分数的计算公式：`分数 = 温度 × w1 + 湿度 × w2 + b`
温度和湿度我们可以通过实时测量得到，那w1、w2和b这三个数呢？目前都是空的，所以模型结构本质是一张蓝图，它描述了：
- 有哪些变量
- 怎么连接
- 怎么计算

但它本身并不包含知识。
### 训练之后得到权重
假设收集到了很多天气数据：
```
温度  湿度  是否适合出门
25    80    否
23    40    是
30    35    是
18    95    否
...
```
训练就是不断调整w1、w2和b，让模型输出更接近真实结果。
经过大量迭代得到：
```
w1 = 0.7
w2 = -0.3
b  = 5.0
```
这三个数就是模型权重。训练结束后，这三个数跟着模型一起保存，原始的训练数据并不会保存。
通俗地来说这三个数其实就是经验的压缩结果，对于绝大多数的训练样本，这组权重是最好的一组，也就是最有经验的。
扩展到大模型就是：
```
简单天气模型：3个参数
大模型：1750亿个参数
```
参数数量扩大了几十亿倍。
而在后续跑的过程中，由代码决定怎么算（计算算法），权重决定用什么数字算（算法参数）
### 加载权重
最常见的是如下代码：
`model.load_state_dict(torch.load("weights.pth"))`
对于前面的简单天气模型，`weights.pth`实际存放的就是：
```
w1 = 0.7
w2 = -0.3
b  = 5.0
```
加载权重的过程其实就是赋值的过程：
```
model.w1 = 0.7
model.w2 = -0.3
model.b = 5.0
```
加载即是`空蓝图+具体数字=完整模型`的过程
### 权重变化
同一个模型结构，可以搭配多种组权重。比如简单天气模型，在地区A时使用权重A进行推断，在地理位置不同的地区B时则使用权重B来推断，因为两地地理形势具有差异，所以需要更适合当地的权重。
简单来说，模型结构就相当于**大脑**，权重就相当于对于某事物的**记忆或经验**。放到大模型上，模型结构即是**神经系统**，权重即是**学到的知识**。
决定模型能力的，一般不是结构文件，而是权重文件。
### 权重参数为什么这么多
在简单天气模型中，`输入数量 = 2; 参数数量 = 2`，显而易见。
但神经网络中规模一大，情况就有变化。假设`1000个输入 → 1000个输出`，如果每个输出都要看到每个输入，则`1000 × 1000 = 1,000,000`就需要100万个权重。
进一步地，`8192个输入 → 8192个输出`，对应`8192 × 8192 = 67,108,864`，单个矩阵就有6700多万个参数。
而大模型的一层里不止一个矩阵。几十层甚至上百层叠起来之后，参数数量很快达到十亿、百亿、千亿级别。所以权重文件越来越大，不是因为代码边复杂了，而是需要保存的数字越来越多了。
假设代码里写着`nn.Linear(768, 768)`，这一行代码只有十几个字符。但它对应的权重矩阵大小是`768 × 768 = 589,824`，接近59万个浮点数。代码描述这里有一个`768 × 768`的矩阵，权重保存的是`矩阵中每一个元素对应的数字`。所以代码描述规格，权重填充内容；规格一句话就能描述，内容可能随之无限增长。
所以，模型代码几十KB，权重文件却大几个GB，甚至几十几百GB。
